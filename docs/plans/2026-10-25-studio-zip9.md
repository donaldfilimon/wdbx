### Verified ZIP 9 API expectations

Installed upstream ZIP 9.0.5 source retains `ZipWriter::new`, `SimpleFileOptions`, `compression_method(Deflated)`, `start_file`, `finish`, `ZipArchive::new`, `by_index`, `len`, `size`, and the `Read` interface. Rust MSRV is 1.88, compatible with pinned 1.99.1. `SimpleFileOptions` is still `Copy`, so the existing per-entry options reuse remains valid. No blanket API rewrite is justified.

The required adaptation is `ZipFile::name()`: ZIP 4 returns `&str`; ZIP 9 returns `ZipResult<Cow<'_, str>>`. Map the decoding error to the existing `MalformedSave` category, then obtain an owned name before mutably reading the file. Do not substitute lossy decoding or sanitized/mangled names: the accepted namespace is exactly `manifest.json` or `assets/<64 lowercase hex characters>`.

ZIP 9's default `by_index` does **not** enforce local/central header consistency. Metadata can collapse duplicate central-directory names, making `len()` and the existing duplicate checks alone insufficient. After the existing archive count check, use `validate_header_consistency()` (which checks duplicates and overlapping entries), map failure to `MalformedSave`, and qualify compatibility against legacy valid archives. This validation can reject formerly accepted ambiguous bytes; document that intentional malformed-input tightening rather than calling it byte-identical behavior.

Preserve bounded in-memory entry reads; do not switch Studio to filesystem extraction. Existing limits are 512 MiB input/aggregate expanded data, 10,001 indexed entries, 64 MiB manifest and 32 MiB per asset, with `take(max + 1)` after declared-size checks. ZIP's parser still allocates metadata before the application's count test; do not claim the migration independently solves parser-allocation limits. Preserve stale-revision refusal, validation-before-recovery-copy/asset writes and snapshot commit order. Export remains temporary-file/write/sync/rename with failed-temp cleanup.

New small, independently generated fixtures should discriminate:

1. A ZIP 4-produced `.wdbxspecimen` with a referenced asset, fractional float and non-ASCII specimen text loads under ZIP 9; original manifest/asset bytes and resulting snapshot values are pinned. Generate with the baseline writer in a disposable qualification checkout, never a live store. A ZIP 9 export reads under the retained ZIP 4 oracle or an independent standard-library reader; compare semantic content, not compressed bytes/timestamps.
2. Duplicate `manifest.json` and duplicate asset entries (both matching and differing payloads), missing manifest, missing referenced asset, corrupt asset hash and unknown members refuse. Build duplicates with an independent writer because ZIP 9's `start_file` rejects duplicate names.
3. Local/central name or size mismatch, overlapping entries, invalid UTF-8 under the UTF-8 flag, truncated data and CRC mismatch fail without changing revision, assets, recovery files or the reopened snapshot. Tests must independently assert fixture structure so they do not accidentally exercise a harmless valid archive.
4. Names containing parent traversal, absolute prefixes, backslashes/drive prefixes, embedded NUL and invalid asset hex refuse. Sentinel paths outside the workspace remain unchanged. Symlink and special-mode metadata must never create links, apply mode bits or cause external reads; the importer treats accepted content as bounded bytes, not filesystem instructions. If adding explicit non-regular-entry rejection, record it as an intentional input-policy tightening and test it separately.
5. Declared over-limit manifest/asset sizes and excessive entry counts refuse before payload writes; a bounded streamed-overrun/CRC fixture proves reads fail closed. Avoid allocating 512 MiB merely to test a limit: use narrowly controlled metadata fixtures, and if a small private limit seam is needed, keep production limits unchanged and test the real defaults separately. Do not introduce a public policy API solely for tests.
6. A valid archive imported with a stale expected revision leaves durable state unchanged; a failed export cannot replace an existing successful archive or leave `.partial` output behind.
