## Executable contract and boundaries

`specimen_kernel::identity::HybridTable` owns insertion-ordered node, entry and supporting-resource records. Its `insert(EntryRecord, Option<NodeRef>)` validates all supplied data before mutation and returns `Inserted`, `Duplicate` or `Full`, or a typed refusal. Each node owns exactly one complete key and population; each node is limited to 20 entries. A valid fresh host ref supplied for entry 21 atomically creates a fresh same-key sibling and adds the entry. Missing allocation returns `Full`; colliding allocation rejects; both preserve prior records and indexes. Empty nodes survive targeted entry removal and remain bound to their original key/population.

`NodeRef(u128)`, `EntryRef(u128)` and `ResourceRef(u128)` are separate concrete types, generated by the host. The table checks one shared concrete-reference namespace across these three types on insert and complete import/rebuild. A reference already naming the same semantic entry is an idempotent repeat; reusing it for different semantics rejects. Exact semantic repeats return the original concrete node/entry, including a retry of a spill request and a changed key projection. A fresh entry ref does not manufacture another copy of an existing semantic entry.

`Population` contains tenant/specimen/node_type. Every lookup requires population; entry get/removal also requires concrete node and entry refs. A target node from another population, or a different key on an existing node, rejects before mutation. Scope parameters are a host contract, not authentication.

`PatternKey` contains encoder_version, modality, resolution and all 32 digest bytes. Keys are caller-prepared candidate routes. No hash/key match deduplicates distinct originals; semantic comparison spans the complete population even across different supplied keys. Semantic equality is exact original UTF-8 bytes plus prepared typed bind/action trees, ordered alternatives, inhibition and exact finite `f64` weight bits, including distinct signed zero. It does not use JSON serialization as canonical authority. Call spelling/text/tree and argument order are compared as supplied; lexical normalization remains later parser work.

Prepared trees use the existing `language::Expr`. Validation walks every supplied tree, checks the existing language contact ledger and the appropriate PatternBind/NodeAction scope, enforces the existing 16-level nesting and 8,000-byte prepared-tree budget, and checks the parser's literal-call shape. The 8,000-node work bound also prevents prepared trees made of huge collections of empty text nodes from bypassing those bounds. Finite weights are required; this packet adds no new numeric weight range or natural-language grammar. Original patterns/resource keys accept at most 2,000 Unicode scalar values and retain their exact UTF-8 bytes.

Each supporting resource has its own `ResourceRef`, owned original, population and complete structural key. `ResourceId(String)` is an optional, nonunique scoped logical link independent of concrete refs and keys; duplicate links and even equal resource originals retain all concrete records. Unlinked resources remain structurally indexed. Logical labels are not foreign-key authority or credentials. An entry's optional resource link likewise does not redefine semantic entry equality. The owned table admits at most 10,000 supporting records; this is the in-memory table bound, not a newly published persistence/import schema.

Collections with up to 64 records in a population use array lookup. Larger collections use multi-value hash lookup rebuilt from owned records; returned order is always record insertion order. Both entries and resources exercise 64/65. Hash iteration order is never observable, and deterministic standard-library hash builders require no random generator. Every rebuild validates refs, node/population/key consistency, tree validity, finite weights, node caps, original bounds, semantic duplicate entries and resource count before replacing any current state. No I/O, clocks, threads, random generator, GPU or new dependency was added.
